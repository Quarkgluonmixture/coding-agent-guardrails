## 工作风格

- **大改默认拆分**：>8 files 或 >1500 LOC 或跨 >1 关注点 → 拆成 2-3 个 chunk，并用一句话向用户说明拆法。

- **数值 claim 必实测**：任何 char/token/byte/size/latency/cost 数字，下结论前先 `wc -c` / `grep -c` /
  读 artifact 实测，**不要套 mental model**（"flatten 后应该短一半"这类直觉常错）。引用实测到的真实数字。

- **下 verdict 前证明信号有解释力**：说「通过 / 在跑 / 没有 / 为空 / 符合」之前，先确认这次检查
  **在正确的对象和最新的产物上真的启动了、并到达了相关断言** —— 核对可得的用例数 / 计数 / 耗时，
  且要对得上**期望值**（4 秒的 macOS CI = 根本没起来；`Executed 0 tests` 是"通过的样子"不是通过；
  零匹配的白名单是**空过**）。
  **负面或空结果多问一步**：在**授权范围内**核上游数据或过滤契约，分清「源头没有」「被过滤器或
  默认值折叠了」「未知 / 未授权」—— ⛔ 拿输出证明输入不存在是循环，⛔ 但也不许为了查证越过授权边界。
  复杂判断按 baseline × 维度逐格实证，区分**设计层 vs 计量层**；cross-X 不对称先查文档/catalog
  是否已处理，别当新 gap 报。⛔ 取不到证据就写「未验证」，说清缺的是**独立 backstop** 还是**根本没验过**。

- **一个事实只设一个权威来源**：判定逻辑、计算值、阈值、规则正文只维护**一份**，其他表示一律
  **派生、生成或显式指向** —— 第二份副本一定会漂移，而**漂移的那份往往正是读者看到的那份**
  （被测到的那份反而是对的 ⇒ 测试全绿、报告干净、产品是错的）。副本不只在代码里：文档/文案里
  手抄的计算值、散文里复述的阈值、指向编号的交叉引用，都算。
  ⇒ 改「读者看到的东西」前先问**这句话/这个数是谁打印的、几个谁**（grep 那段字面文案，别只 grep
  变量名）；时点快照要留值就带**日期 + 真相源 + 可执行的复算方法**（⛔ 写不出复算方法就别写这个数，
  ⛔ 更不许写「变了记得回来改」）；⛔ 发现不一致先钉定义，别写第三个数。
  （更窄的禁令优先：git 状态一律不 pin，见 `git-and-style`。）

- **⭐ 破坏性操作前先证明目标不是别名**：删除 / 覆盖 / `reset --hard` 之前，把目标**canonicalize**
  （realpath），并证明它和源、和权威副本**不是同一个对象**。逻辑路径、symlink、`cp -R` 的复制语义
  会让一个"临时副本"其实就是真东西——本 repo 的测试删掉过自己的 `.git` 并照常打印 ALL SUITES PASS。
  链条与每一步的反制写在 `tests/lib-testkit.sh` 头部。

- **审计 prompt 保持 lean**：⛔ 不要枚举 attack vector / 检查项——枚举会造成 list-shaped blind spot，
  漏掉清单外的问题。给 persona + scope + 输出格式即可。

- **大范围改动 / 审计前把文件读全**：先完整读一遍再动手，⛔ 不要只靠 search 片段下判断——片段看不见
  调用方、早退分支、和文件末尾的覆盖写法。

- **token-heavy 活外包**：批量 inference / 长摘要 / 独立审计交给独立 subagent、另一谱系或小模型，
  配 done-monitor，⛔ 不在主循环里 poll 等。

- **⭐ 文档里的结论 ≠ 承载系统里的状态**：收尾时去**外部系统**（PR / 部署 / 看板 / 远端分支）
  读回来确认，⛔ 别拿自己刚写的那份文档当证据。（"推送成功" ≠ "PR 看到了"。）

- **A/B 否决的是这版实现，不是方向**：revert 后别只记负结果——问"真实意图是什么，有没有符合蓝图
  的 reframe"（常见拆法 = 安全的展示半可直接 ship + 风险的行为半重塑后按门槛再进）。原因记入 ledger。

- **新依赖 7 天冷却**（这条是**风险偏好不是不变量**，项目可显式覆盖）：不装发布未满 7 天的包
  （投毒多在发布后数小时到数天内被撤下）。npm：`.npmrc` 的 `min-release-age=7`（需 npm ≥ 11.10，
  旧版**静默忽略**）+ dependabot `cooldown`；紧急补丁显式破例 `npm i --min-release-age=0 <pkg>`。
