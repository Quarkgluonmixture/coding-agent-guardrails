# 静默降级与相关故障 — 案例档案

**触发**：写 `except`、写兜底路径、写能力探测、写重试、接别人的宿主扩展、或在诊断
「日志和页面看起来都正常但结果不对」时读一遍。规则正文在
`rules/global/coding-practice.md`；这里是它每一条背后的实盘代价。

---

## ⭐ 静默降级比崩溃更贵

吞掉异常退到兜底路径的 `except`，会让**每一次**调用都悄悄变坏，而日志和页面看上去仍然正常——
最后发现它的通常不是测试，是用户。

- **markdown-it linkify（2026-08-27）**：开了 `linkify` 但 `linkify-it-py` 没装，它**在每次
  `render()` 时**才抛，被 `except Exception` 吞掉退到转义纯文本 ⇒ 连续 6 份报告的标题都是
  字面的 `##`，是用户在手机上看到 `#` 才发现。
- **subprocess locale（2026-06-20）**：调度器用 `subprocess.run(text=True)` 捕获 stdout，即用
  **进程自己的 locale** 解码，而这个 locale 跨启动路径不稳定（`.cmd` 拉起 = cp936，直接 spawn
  = UTF-8）。不匹配就在 reader 线程里 `UnicodeDecodeError` ⇒ capture 返回**空** ⇒ 上层判成
  「脚本没输出，跳过 AI 调用」。**一个月的邮件因此被误判成模型判断差。**
- **同族两次**：插件只在 config 配、`check_requirements()` 只读 env ⇒ 判未配置且**零报错**，
  只是启动行里少一个平台；`pythonw.exe` 没有 stderr ⇒ `logging.basicConfig` 的日志全丢，
  而那个服务唯一的访问控制就是身份头，拒绝记录丢不起。
- **能力探测（2026-08-30）**：`command -v python3` 会命中 Microsoft Store 占位壳（一执行才打印
  "Python was not found"），于是 doctor 报了 "python3 available"。⇒ 探测就真的调用一次。

## 走宿主的正规入口，不是「能跑的那条分支」

拦截点常在你那条分支**之前**，改它救不了。

- **投递平台（2026-08-26）**：自定义投递目标有能发送的特例分支，但 dispatch **之前**的
  `_is_known_delivery_platform()` 不认它 ⇒ 5 个 job 全 `blocked_config`、`no LLM call was made`。
- **空 api_key**：`api_key: ''` 落进「已知 provider + 有 base_url + key 为空 ⇒ 交下游解析环境
  变量」的分支，而下游**不解析**这个 provider ⇒ 送空 token → 401。同一个 key 主模型能用，因为
  走**另一条解析路径**。⇒ 空字符串不是「未设置」；⛔ 别拿 A 路径的成功证明 B 路径的配置对。

⇒ 接入前先 grep 出宿主的注册表 / 校验函数 / 发现路径，按它要的形状注册齐——缺一件就是静默不加载。

## 重试与降级的粒度要对准失败的阶段

- **哪个阶段有队列（2026-07-07）**：只给「投递」写了重试队列、「生成」失败没有 ⇒ 一次 DNS 中断
  把整份日报直接丢掉，什么都没排队。列出流水线各阶段，逐段回答「这里失败了谁接住」。
- **次数和退避上限要一起看**：`max_retries=3` 配 `2→60s` 指数退避 ≈ 只有 7 秒窗口，**根本够不到
  60 秒那档**。公式没错，瓶颈是次数（改 6 ≈ 1 分钟）。
- **瞬时错误分类器要窄**：marker 里 ⛔ 不放裸的 `failed` / `error`，否则 422、空输出、逻辑 bug
  全进重试 = token 黑洞。
- **同一状态码下的子码是不同故障类**：429/1305 临时过载（退避有用）vs 429/1308 五小时硬配额墙
  （带 reset 时间，重试 6 次也没用）。⛔ 别按 HTTP 状态码一刀切。
- **补跑走和正常完成完全同一条终态持久化路径（2026-08-26）**：`_mark_rerun_status` 开头
  `if job.get("repeat"): return`，而每个 recurring job 都带 `repeat` ⇒ early-return **永远命中**，
  补跑成功一次都没回写过 `last_status`，看板长期挂着一个已自愈的红。

## 测试断言的形状 —— 以及 14/17 条测试的零收益

（`work-discipline` 管「这次检查有没有真启动、到达断言」；这里管**跑起来了但断言形状不对**。）

### ⭐⭐ 实测一次：加一条能力 = 8 个产品文件 vs 17 个测试文件

2026-09-01，人问了一句「这些测试是必要的还是工程完美主义」，于是量了。那 17 个里：

- **3 个有防御价值**：accepted 清单（记录「这条能力是个决定」）· 一条反面守卫**按它自己写的方式
  退休**（失败信息里写着「若真做了这个功能，请把它加进清单并换成正面断言」）· 一条行为 pin
  逼作者确认重构没改坏三态。
- **14 个是冻住的全局计数与清单副本**（`== 52` · `food.count == 16` · 同一份路线清单在 6 处各存
  一份）。⛔ **那晚一个 bug 都没抓到**，只是让人把同一个列表重打了 6 遍。

⚠️ 机制：那些 `== 52` 本来想表达「**我这片**没动东西」，却冻住了一个**全局**数 ⇒ 任何**后来**的
合法新增都让它们全红。它们表达的是一个**关系**（覆盖表 ≡ 导航地图），⛔ 却写成了一个**快照**。
⭐⭐ 这就是「一个事实只设一个权威来源」漂移在**测试里**，而且**被测到的那份是对的、抄出来的
那 14 份是错的**。

### ⭐ 判据（最锋利的那一句）

一个断言写成 `== <当期全局值>` 之前先问：**我要说的是「我没动它」，还是「谁都没动它」？**
前者是**关系式**，后者才是**快照**，而后者几乎总是错的。

### 收敛做法（已交付，2026-09-02：测试改动面 17 → 3 个文件）

1 份权威 + 一条**形状**断言（每条能力恰好画一处、分组穷举），各处的 `== 52` 换成关系式：
`entries.count == AppNavigation.capabilities.count`（覆盖表与地图逐条对齐）、
`capabilities.count == acceptedCapabilityIDs.count`（权威是那份**决定登记册**）、
分类计数从同一份登记册**派生**。⛔ **一条闸门都没砍** —— 迁移/授权闸、采集语义、变异验证、
反面断言全留着；探针期间 `eachDeclaredSheetIsOpenedByExactlyOneRoute` 还真抓到一次偷懒共用 sheet。

⭐⭐ **怎么量这件事**（可迁移）：**塞一条假能力进权威清单，然后数还有谁红。** 红的数量就是
「加一条能力的测试改动面」。⚠️ 这是唯一能把「工程完美主义」变成一个数的办法 —— ⛔ 别靠感觉判断
测试多不多。同族的坑后来又踩了两次（路线清单、契约版本号），都是同一个机制。

⚠️ 唯一该**故意**冻的是**阈值 / 预算**：那里红本身就是产物（它逼你做交换），且失败信息必须说清
该做哪个交换。⛔ 别把预算「修」成跟随自身用量的关系式 —— 跟随用量的预算不是预算。

- 上面那次 linkify 降级测试**全绿**——只断言了「零外部请求」和「字节数」，转义纯文本这两项全过。
  ⇒ 补的是正向结构断言：`## → <h2>`、`**x** → <strong>`、列表 → `<ul>/<li>`、代码块 → `<pre>`，
  外加「可见文本里不许残留 markdown 语法」。
- **对基线要逐条对，不看总数**：`14 failed / 918 passed 与基线逐条一致` 才叫没回归。
- **先把偶发挑出来**：某测试跟着改动一起红、隔离跑全绿、再跑全量又绿 ⇒ 别当回归，也别当「已修」。
- **测试必须隔离状态根**（`APP_HOME` 这类）：不隔离会污染实盘 `logs/errors.log`，之后所有
  诊断都建在脏数据上（踩过）。

## 改别人的代码：扩展点 > 补丁，配置 > 源码

- **别急着硬 fork，先量一次冲突（2026-08-26）**：实测落后 15,440 commits 的上游、本地只有 685 行
  改动，试合**只冲突 5 文件 14 块**；而 fork 等于自己维护两万行的核心文件。
- **能用配置解决就不改源码**：源码里的 `base_delay` 改了会被下次 update 清掉，同一效果落在
  config 上就活得下来。
- **补丁要搬到合并线之外**：把本地补丁搬成插件时，放**仓库外**的用户插件目录才真正脱离冲突；
  放 repo 内的 `plugins/` 仍坐在 git 工作树上。
- **未提交的本地补丁会被上游更新器吞掉**（它走 `stash --include-untracked` + `reset --hard`，
  不是 merge）⇒ 留 `<file>.bak-<feature>-<date>`，并在项目文档写清「更新后怎么复原」。

## 默认值往安全的方向倒 — 每条的来历

- **副作用默认关**：邮件脚本默认 dry-run，只有 `--commit` 才推进 `seen_ids` ⇒ 手工测试不可能把
  邮件标记成已读。（没这条之前，一次手跑叠上编码 bug 埋掉了一天的邮件。）
- **兜底取最严那档**：没声明来源的报告兜底成最高敏感度 / 最长保留，**显式声明**才降级。
- **fail-closed 要在碰数据之前**：先校验身份再碰存储，未授权者连「这东西存不存在」都问不出来；
  且只绑 `127.0.0.1`——⛔ 绑 `0.0.0.0` 等于让人绕过上游注入身份头的那一跳。
- **缺失优于错误**：抽不出摘要就**整个 key 省略**（⛔ 不是空字符串——消费端 fallback 才接得住）。
  抓错的摘要看起来很权威、会一直误导下游；曾把小节标题「这是干嘛的」当摘要发出去。
- **不给打不开的门按铃**：推送前先确认这个身份打得开目标页，否则只写存档不推送——一条点开是
  403 的通知比不通知更糟，它花掉了那一眼却什么也没给。
