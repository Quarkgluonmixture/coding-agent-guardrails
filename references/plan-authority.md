# 计划权威按问题划界

**触发**：你正要新建或大改一份会回答「顺序 / 进度 / 未完的活 / 下一步」的文档
（roadmap / plan / implementation / 交接页）。资格线（**已常驻**）：
`rules/global/memory-hygiene.md` —— 同一范围同一问题只能有一个 live 真相源，
判据在**动笔那一刻**生效。

## 为什么会反复发生

**新建一份比读懂并更新已有的那份便宜。** 所以这不是纪律问题，是成本问题 ⇒ 判据必须在动笔那一刻
就生效，⛔ 不是事后清查。

## 怎么判

- ⛔ **别按文件名执法**：决策记录、参考资料、归档、交付物模板都可以合理地叫 plan/roadmap，
  它们**不参与调度**，不算 live 计划。判据是「它回不回答顺序/进度/下一步」。
- 多份 live 计划并存是允许的，前提是各自开头写清：**我回答什么**、**我依赖谁 / 取代谁**。
- 非权威处**只链接或派生**，⛔ 不手抄状态。

## 两条容易反向踩的

- ⛔ **不写 live 进度的文档，也不许把 durable 的东西关在 live 文档里。** 把进度清出决策文档时，
  其中**修正了设计声明**的那几句必须**回写**决策 / 契约文档 —— 否则只是把陈旧问题倒了个方向：
  durable 结论被困在下一个 session 会刷掉的快照里。
- ⛔ **ID 冲突不靠重编号解决**（会打断已经引用它的契约与历史）。引用时带前缀限定：
  `IMPLEMENTATION:P5`、`GOTCHAS:22`。
