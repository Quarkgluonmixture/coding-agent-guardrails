# /deep-dive — 深挖

「深挖 <任务>」= 先把**足以改变判断**的 prior work 研究透并裁决，再按 phase 自走做完，只在真实 gate 停。
每一步说清它回答了什么、证据在哪；标明已核验 / 推断 / 未知，⛔ 不编。
**形状不预设**：产物的形式、粒度、数量按任务定，深度与决策代价成比例。
宿主有 checkpoint / authority 等机制时沿用；没有就按任务自然继续，不另建状态系统。

## 研究段：prior work → 裁决

1. **目标**：这次要回答什么、作出什么决定或交付什么，怎样算达成；哪些未知量会改变判断。后续研究与执行都以此为边界。
2. **内部 prior work 先看**：已有的实现、实验、决策、失败记录说了什么、证据在哪、条件变没变。没有就写无。
3. **广度**：用互补的发现路径建 landscape，直到主要方法族、关键分歧和可能改变选择的反例已显现。
   同一证据链不重复计数；决定性主张追到原始依据，追不到标未核验。
   当补充发现已不再实质改变候选、适用边界或取舍依据时停；说明据哪些补查作此判断，以及仍有的覆盖缺口。
4. **深读**：选信息价值最高的材料（最像、最强、最新，或能推翻主流的），说明为什么是这几个。读原始材料，读到能回答：
   它在什么设定下解决了什么、靠什么机制、哪些假设在本任务成立或不成立、证据在什么条件下成立、哪里失效、
   能搬走什么、读完还缺什么。没有的信息写未知，⛔ 不强造缺陷。
5. **裁决**：⛔ 不以资料汇总结束。说清已有工作解决了什么、能直接复用什么、什么不适用及为什么、还剩什么真正要解决（可为空）。
   仍可能改变选择的未知量写出「若 A 怎样、若 B 怎样、什么证据能区分」：能低成本补查的先补，必须实验的转成待检验主张。
   证据不足就做暂定裁决并安排区分性验证，不包装成已证实。
   **exit**：现有证据已足以选择下一步；仍可能改变选择的未知量，已安排能区分它的行动。「搜了很多」「读了几篇」不是 exit。
   裁决后，目标尚未达成就直接进入执行段，⛔ 不另问是否开始；目标已达成则直接收尾验收。
   学习任务须用机制推导未直接照搬材料的例子，并核查结果、交代边界与未知。

## 执行段：按 phase 自走

6. **roadmap**：从裁决列出 phase 的顺序、每个的目的与完成判据；只细拆当前 phase。
7. **最小可关闭单元**：动手前说明本单元要解决什么、范围与依赖、什么证据算完成；大小以能判断结果、控制失败影响为准。
   探索型单元预先说明要区分什么、怎样判断；支持、否定或仍不确定都可作为结果，但执行失败或缺少观测不自动满足 exit。
8. **执行 → 验证 → reconcile → 落盘 → close**：只做 scope 内的事。验证对准待检验的主张：检查真的跑到了断言、数字是实测的，
   取不到证据写未验证。结果对照预写的 exit；未满足就修复、换路径或标明阻塞。偏差若改变后续判断，先更新受影响的
   roadmap 与依赖，再继续，不为已有结果降标。结论写到该在的地方（有文件系统写文件，没有就在对话里给出可定位的证据）。
   证据支持预写的 exit 成立才 close；未验证的主张保留未完成。
9. **冻结与 reopen**：已关闭的默认冻结；新证据只 reopen 结论可能失效的部分并沿依赖检查，⛔ 不全局重来；重试须有可能改变结果的依据。
10. **自走**：事实与约束足以定下一个单元就直接进，可逆的实现选择自己定。收尾回到第 1 步的目标逐项验收，单元全关 ≠ 任务达标；
    资源用尽仍未达标就交付结果与缺口，标未完成。
11. **真实 gate 才停**：下一步缺授权或资源、依赖不可用、或需要只有用户能给的信息或取舍且没有低成本验证能替代。
    不可逆、外发、花钱的动作先核已有授权。停下时说清已完成及证据、卡在哪、要定什么、各选项代价。
